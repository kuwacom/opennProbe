# ベンチマーク

測定: `scripts/bench.sh`(`/usr/bin/time -v` の経過時間と最大 RSS)。32 vCPU の共有マシンで、他の処理と同時に動いているので
経過時間は ±20% 程度ぶれる(2 回の測定・各 3 回の中央値)。pps は pcap のレコード数 / 経過時間。

入力は CSE-CIC-IDS2018 の pcap:

| 名前 | 内容 | レコード数 | フロー数 |
|---|---|---:|---:|
| A | 2/14 UCAP 端末(攻撃を受ける側。850 MB。公式 12 本で最大) | 4,718,327 | 288,914 |
| 12 本 | 公式 12 本(2/14 9 本・2/21 3 本。合計 2.55 GB) | 7,384,244 | 約 44 万 |

| 調査用プロトタイプ(Python) | official | なし | 141.4 | 33 k | 2,210 MB |
| v2(ALT_* 列あり) | official | あり | 4.2 | 1.12 M | 130 MB |
| v2(ALT_* 列あり) | official | なし | 4.3 | 1.10 M | 123 MB |
| v3 | official | あり | 2.68 | 1.76 M | 107 MB |

nprobe モードは SECOND_BYTES の秒スロット(向き別のバイト列)を持つぶん少し遅く、RSS も数 MB 多い。

## 改善の段階(入力 A・official)

| 段階 | 内容 | L7 あり 秒 / RSS | L7 なし 秒 / RSS |
|---|---|---:|---:|
| v0 | 移植直後(mmap・行はすべてメモリ) | 4.44 / 961 MB | 4.17 / 953 MB |
| v1 | 読み終えた pcap のページを madvise で手放す | 6.00 / 178 MB | 4.38 / 170 MB |
| v2 | 行を外部安定ソート(64 MB ごとに一時ファイルへ)・再送候補 C の区間追加を速く | 5.37 / 127 MB | 3.65 / 120 MB |
| v3 | 製品出力: ALT_* 列と再送候補のグリッドを外す・到着間隔を時刻列でなく逐次集計に | 2.68 / 107 MB | 1.59 / 98 MB |

v2 までの数値は当時の測定(混み具合が違うので v3 の表とは直接比べない。同じ時間帯に測った v2 は上の表の 4.2 / 4.3 秒)。
v3 の速さは主に、再送候補 C(区間集合)などの調査用の計算をやめたことと、向き別の到着時刻を全部持たずに
個数・和・二乗和だけを持つようにしたこと(フローごとのベクタ確保がなくなる)による。
v3 の RSS の大半は出力行のテキスト(入力 A で 55 MB。`--spill-mb` 未満なので一時ファイルは使わない)。

## ホットスポット(v3・入力 A・gprof)

| L7 なし | 割合 | L7 あり | 割合 |
|---|---:|---|---:|
| `RowFormatter::emit`(列の整形・行の保持) | 21% | nDPI 内部(合計) | 約 40% |
| `FlowBuilder::add`(表引き・分岐) | 18% | うち MD5(SSH の HASSH などの指紋) | 11% |
| `PcapReader::next` | 17% | `FlowBuilder::add` | 12% |
| `FlowBuilder::expire`(期限のヒープ) | 12% | `parsePacket` | 10% |
| `parsePacket` | 10% | `RowFormatter::emit` | 9% |
| `FlowBuilder::count` | 7% | `PcapReader::next` | 8% |

試して効果が測れなかった(ぶれの範囲内)ので入れなかったもの:

- 期限のヒープに積むのを「期限が早まったときだけ」にする(延びた分は取り出したときに入れ直す)
- nDPI の TLS 指紋(JA3/JA4・証明書 SHA1)の計算を設定で切る(SSH の指紋には設定が無く、入力 A は SSH が多い)

L7 ありの残りは nDPI 本体の判定処理で、判定結果を変えずに減らせる余地は小さい。
